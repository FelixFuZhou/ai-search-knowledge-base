## 每题的特有难点提示

> 提示只给**这道题区别于骨架通用部分的地方**。骨架的八段照常走。

### D2 · 保险理赔 agent（Scale AI）

- **题眼是「同时控制 token 成本」** —— 这是明确写在题里的约束，必须在设计里正面回应，不能只说「用 RAG」
- 成本手段要具体：分级路由（简单理赔走规则/小模型）、检索 top-k 收敛、prompt caching、**只对可疑单走完整 Agent 流程**
- 高风险维度：理赔审批是不可逆写 + 有合规要求 → 拒赔必须可解释、可申诉、留证据链
- 必答：**什么情况转人工**（金额阈值、证据冲突、历史欺诈信号）

### D3 · Spotify 客服 Agent（Sierra）

- 题眼是**规模**：客服流量大、意图多。所以第一层应该是 **router 而不是 ReAct**（接 [Q37](../题库/E-编排多Agent与协议.md#q37)）
- 意图分类 → 每类走各自的确定性流程；只有开放咨询类走 Agent
- 必答：**转人工的触发条件和交接内容**（用户情绪、连续失败、超预算、高价值用户）
- 必答：账号安全类操作（改密码、退订、退款）的鉴权，客服场景是社工攻击高发面

### D4 · 集成第三方数据（Sierra）

- 题眼是**不可信外部源** → 直接接 [Q43](../题库/E-编排多Agent与协议.md#q43) 和 [Q53](../题库/G-安全与上线.md#q53)
- 三条主线：数据可信度分级、时效与一致性（第三方数据延迟/不一致怎么办）、第三方不可用时的降级
- 必答：第三方返回的内容是**数据不是指令**，且不能与系统指令同权

### D5 · 推理 batching 系统（Anthropic）

- 完整采分点见 [Q11](../题库/B-推理与服务基础设施.md#q11)
- 讲的时候骨架要**换一套**：这题没有工具契约和审批。用「核心张力 → 调度策略 → 显存约束 → 失败模式 → 指标」的结构
- 必答：TTFT / ITL 分开、continuous batching、KV cache 是 batch 上限、过载快速拒绝

### D6 · GPU 配额系统（OpenAI）

- 完整采分点见 [Q16](../题库/B-推理与服务基础设施.md#q16)
- 必答：配额/限流/计费三件事分开；token 而非请求数计量；预扣+结算；RPM+TPM 双维度；429 + Retry-After

### D7 · 多模态文件上传（xAI）

- 骨架适用，但重点在**管道**而非 Agent 循环
- 主线：分片上传 + 断点续传 → 类型检测（不信扩展名）→ **安全扫描**（恶意文件、隐藏 payload）→ 解析（PDF/图片/音频各自管道）→ 存储与生命周期 → 送进 context 的表示形式
- 必答：**大文件不能整个进 context**，要摘要 + 按需检索（接 [Q30](../题库/D-上下文RAG与记忆.md#q30)）
- 必答：上传内容是**间接注入面**（PDF 里可以藏指令）

### D8 · 跨会话记忆（OpenAI）

- 直接接 [Q35](../题库/D-上下文RAG与记忆.md#q35)，这题是它的完整展开
- 主线：**写什么**（写入门禁，不是模型想写就写）→ **怎么存**（结构化 + 来源 + 时间）→ **怎么读**（相关性检索而非全量注入）→ **怎么删**（用户可见、可编辑、可删除，且触达所有衍生索引）
- 必答：记忆是**不可信数据**，不能当指令、不能当授权
- 必答：用户对记忆的**可见性和控制权**——这是产品要求也是合规要求

### D9 · 统一查询引擎（Glean 类）

- 题眼是**跨源权限**：每个源的 ACL 不同，且会变。必须在检索层做，且要处理权限变更后的索引更新
- 混合检索必答（专有名词、人名、邮件主题靠 BM25，语义靠向量）
- 时效必答：邮件和聊天是时间敏感的，「最新的那封」是高频查询意图
- 必答：**权限泄露是这类产品的头号事故**——负向测试要覆盖跨部门、离职员工、共享文档的权限继承
